# Case packs

The app is an engine plus a **case pack**. The engine (search, assistant, Knowledge Studio, scenarios, hazard and predictive models, reports, server) is the same for every plant. Everything that describes one plant lives in `cases/<id>/`. A new case means a new pack, not new code.

```
cases/<id>/
  plant.json        compact description you write (optional, compiled into the files below)
  kb.json           equipment sets, assets, documents, text chunks, instruments, OPLs, nozzles, parts, data issues
  dsil.json         datasheets and interlock logic per equipment tag
  ga.json           parts list and nozzle table per set (optional, generated from kb.json when missing)
  mh.json           maintenance work orders
  eval_cases.json   questions with known answers, scored on the Governance page
  case.json         names and wording shown in the app (title, subtitle, example questions)
  geo/*.js          hand-drawn geometry (optional). Anything missing is generated by src/modules/auto.js
```

Build and check one case:

```
python3 tools/pack_validate.py <id>       # schema and cross-reference check
python3 build.py <id>                     # writes dist/index.html and the single HTML file
BUILD_OUT=/tmp/x python3 build.py <id>    # throw-away build, leaves dist/ alone
node tests/smoke_case.js dist/index.html  # works for any case
node tools/case_shots.js dist/index.html /tmp/shots   # screenshots of every page, fails on any script error
```

`lldpe` is the original case (hand-drawn P&IDs, 3D models and scenario rules). `mock-cdu` is a 7-set crude distillation unit made only from `plant.json`, with no drawn geometry, and shows what a new case looks like on the first build. `_template` is the smallest useful starting point.

## The fast route: write plant.json

You describe each equipment set once. `python3 tools/pack_build.py cases/<id>` then creates every file above, including document records, the searchable text chunks, interlock and datasheet records, nozzle and parts tables, work orders (synthetic ones if you supply none, each marked "SYNTHETIC") and 50 or more evaluation questions whose answers come from your own data.

Per set (only the first group is required):

| Field | Meaning |
|---|---|
| `tag`, `name`, `unit`, `area`, `fluid`, `crit` | identity. `fluid` drives the hazard model (see below). `crit` is e.g. `HIGH CRITICAL` |
| `kind` | `pump`, `comp`, `fan`, `valve`, `hx`, `fired`, `column`, `reactor`, `drum`, `vessel`, `dryer` or leave out (guessed from the name) |
| `pid` | `ref`, `title`, `sys`, `process` (the paragraph the assistant quotes) |
| `ga` | `length_mm`, `height_mm`, `cl_mm`, `weight_kg`, `motor` |
| `pp` | `footprint` ("5.0 x 3.5 m"), `grid` ("B-2"), `elev` |
| `assets` | other tagged items of the set (tank, motor, burner ...) |
| `instruments` | `tag`, `type`, `var`, `sp`, `act`, `eq` |
| `datasheet` | `title`, `no`, `sections: [[name, [[label, value], ...]], ...]` |
| `interlock` | `logic` (SEQ-101), `sil`, `desc`, `effects: [..]`, `triggers: [{c, tag, sp, vote, fx:[1,0,..]}]`, `permissives: [[no, text, tag]]` |
| `nozzles`, `bom` | tables of the GA drawing; they become the clickable parts and nozzles |
| `opl` | one point lessons: `title`, `cls`, `obj`, `steps: [[text, check]]`, `cases: [[symptom, cause, action]]` |

At top level: `case` (id, title, subtitle, company, code, brief), `documents` (extra narrative documents with `text`), `history` (`{"source":"synthetic"}` or `{"source":"mh.json"}`).

See `cases/mock-cdu/plant.json` for a complete example and `cases/_template/plant.json` for a minimal one.

## Real work orders

`python3.13 tools/pack_import_mh.py "History.xlsx" cases/<id>/mh.json` reads an Excel or CSV export. Column names are matched by synonym (WO_Number, Work Order, Order No ...). Then set `"history": {"source": "mh.json"}` in plant.json and compile again. Run it with `python3.13` if the default python cannot import openpyxl.

## Reading the case documents quickly

`tools/pdf_pages.sh <file.pdf> [out-dir]` splits a PDF into per-page text and PNG images. Pages with almost no text are scans: read the PNG. No OCR is installed.

## What the engine generates when geo/ is empty

| Missing file | Generated by | Quality |
|---|---|---|
| `geo/pid.js` | `autoPid`: equipment symbol by kind, process lines, valves and instruments from the instrument list, trip row, interlock panel, cause and effect map | clean schematic, good enough to demonstrate |
| `geo/gad.js`, `geo/g3m.js` | `autoGad`, `autoG3m`: banded sections from the parts list, nozzles from the nozzle table | schematic |
| `geo/plot.js`, `geo/p3.js`, `geo/ov.js`, `geo/h3.js` | grid layout of the sets | fine up to 8 sets |
| `geo/scn.js` | chain reaction rules from the stream list and trip set points | assumptions, listed in the register |
| `geo/hse.js`, `geo/alias.js`, `geo/eqn.js` | defaults and names from the data | fine |

To improve one equipment set later, copy the relevant section of `cases/lldpe/geo/<name>.js`, edit it, and put it in `cases/<id>/geo/<name>.js`. A geo file replaces the whole generated block for that name, so include every set in it.

## Fluids and the hazard simulator

The hazard simulator needs the `fluid` text of a set to contain one of: ethylene, propylene, propane or LPG, butane, hexane, pentane, hydrogen (H2), fuel gas, methane, benzene or toluene, methanol, naphtha, gasoline, kerosene, diesel or crude. Anything else is treated as non-flammable and skipped. Add a fluid in `src/modules/hse.js` (`HSE_F` and `HSE_RE`).

## Known limits of the generated geometry

- Plot plan, 3D plant layout and overview are laid out for up to 8 sets (4 by 2). More sets render but are small.
- 3D models of generated sets are banded cylinders and boxes keyed to the parts list. They select and animate correctly but do not look like the real machine.
- The case wording in a few static places (Governance roadmap text, the demo walkthrough, My work demo accounts) is generic. Check `tools/text_audit.js` output for any leftover wording from another case: `node tools/text_audit.js /tmp/t.json dist/index.html` then search the JSON for the old plant's names.
