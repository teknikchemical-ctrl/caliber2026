ASSET KNOWLEDGE PLATFORM
Putting it on Netlify with the free Google Gemini AI
=========================================================================================

When you are done you will have a web address anyone can open. Knowledge items, approvals,
imported work orders, feedback and the question log are shared between everybody who uses it,
and the assistant uses Gemini to write its answers. The Gemini key stays on Netlify's server
and is never sent to the browser.

It costs nothing on the Netlify free plan and the Gemini free tier, with no credit card, as of
when this was written. Check both sites' current terms. Set aside about 15 minutes.


BEFORE YOU START
-----------------------------------------------------------------------------------------
- A GitHub account that can see  teknikchemical-ctrl/caliber2026
- A free Netlify account (sign up with GitHub): https://app.netlify.com/signup
- A Google account, for the Gemini key
- The code lives on the branch  claude/great-tesla-l0uw33. You can deploy that branch as it
  is, or merge pull request 1 into main first and deploy main.


STEP 1. GET THE GEMINI KEY
-----------------------------------------------------------------------------------------
1. Go to https://aistudio.google.com and sign in.
2. Click "Get API key", then "Create API key". Make a new project if it asks. Any name will do.
3. Copy the key. It starts with AIza.
   Keep it to yourself. Don't paste it into the code, a chat or an email.

The free tier has per-minute and per-day request limits, and Google may use free-tier prompts
to improve its products. So don't put confidential plant data on a public site.

The project is set up for the model gemini-2.5-flash. If AI Studio shows a different free
model, use that name in step 3. If a name doesn't work, the app tries gemini-2.0-flash and
gemini-1.5-flash next.


STEP 2. CREATE THE SITE ON NETLIFY
-----------------------------------------------------------------------------------------
1. Log in at https://app.netlify.com
2. Add new site > Import an existing project > Deploy with GitHub. Let Netlify see your
   repositories. If caliber2026 isn't listed, use "Configure the Netlify app on GitHub" and
   give it access to that repository.
3. Pick  caliber2026  and choose the branch.
4. Leave the build settings alone. netlify.toml already sets them:
      Build command      python3 build.py
      Publish directory  dist
      Functions          netlify/functions
   If the fields come up empty, type those three values in.
5. Don't press Deploy yet. Do step 3 first.


STEP 3. ADD THE ENVIRONMENT VARIABLES
-----------------------------------------------------------------------------------------
Site configuration > Environment variables > Add a variable. Add these:

   AI_API_KEY      the key from step 1                       (required)
   AI_PROVIDER     gemini
   AI_MODEL        gemini-2.5-flash
   AI_DAILY_MAX    600       total AI requests per day for the whole site. Keep it below the
                             daily limit AI Studio shows for your key.

Optional:
   AI_RATE_PER_MIN  12       requests per visitor per minute
   AI_RATE_PER_DAY  120      requests per visitor per day

Mark AI_API_KEY as secret if Netlify offers the option.

Netlify reads these when it builds. If you add or change one after the first deploy, go to
Deploys > Trigger deploy > Clear cache and deploy site.


STEP 4. DEPLOY
-----------------------------------------------------------------------------------------
Press Deploy. The first build takes one to three minutes. When Deploys says Published, the
site is live at an address like  https://something-123456.netlify.app. You can rename it under
Site configuration > Site details > Change site name.

If the build stops because python3 isn't found, add  PYTHON_VERSION = 3.11  and redeploy. The
finished page is also in the repository as dist/index.html, so another way out is to clear the
Build command, keep the publish directory as dist, and redeploy.

Deploy from GitHub, not by dragging a folder in. The shared database and the AI are Netlify
Functions, which need the full build.


STEP 5. CHECK IT WORKS
-----------------------------------------------------------------------------------------
1. Open the site. At the bottom of the left menu you should see two green dots:
      Shared database online
      AI connected
2. Click the gear next to them. Press "Run diagnostics". Each line should say OK. It will
   name the problem if one isn't, for example a key that isn't accepted or a model name that
   doesn't exist for your key. "Test the AI connection" asks the model one short question.
3. Open AI Assistant and ask:  What is the start permissive for the recycle gas compressor
   KC-4501?  The answer should appear word by word, with numbered sources and a confidence
   level.
4. Open the site in a second browser or a private window. Add a lesson in Knowledge Studio
   in the first one. It should show up in the second within about 15 seconds.

You can also open  /api/health  on your site. It should show "store":"ok" and
"configured":true under ai. The key is never shown there.


IF IT DOESN'T WORK
-----------------------------------------------------------------------------------------
Footer says "Local only"
   The page can't reach the functions. Check you deployed from GitHub and that Deploys >
   Functions lists ai, kb, embed, health and selftest.

/api/health says "store":"error"
   Netlify Blobs isn't available to this deploy. Redeploy from GitHub.

Footer says "Search only (no AI key on the server)"
   AI_API_KEY is missing, or you added it after the last deploy. Add it and deploy again.

Test says "AI provider error" or HTTP 502
   Wrong key, a model name your key can't use, or Google refused the request. Run diagnostics.

Test says "daily AI budget used up" or HTTP 429
   You hit AI_DAILY_MAX or the visitor limit. The assistant keeps answering from the records
   and switches back to the AI the next day or when you raise the limit. If Google's own free
   quota runs out, the same thing happens until it resets.

Answers are slow
   The free tier is slower at busy times, and the first request after a quiet spell has to
   wake the function up.


LIMITING WHO CAN CHANGE THINGS (optional, still free)
-----------------------------------------------------------------------------------------
The site starts open. To add some control, set these in Netlify and redeploy:
   EDIT_CODE      needed to save anything to the shared database
   APPROVE_CODE   needed to approve knowledge items (give it to your reviewers)
   ADMIN_CODE     turns on backup, restore and clean-up under Settings > Administration
Anyone can still read and ask questions. People type the codes once under Settings > Access
codes, and the browser remembers them. They are shared passwords, not personal logins.


GOOD TO KNOW ABOUT A FREE, OPEN SITE
-----------------------------------------------------------------------------------------
- Anyone with the address can read, add and (without APPROVE_CODE) approve knowledge, and use
  the AI up to your limits. Only share the address with the people you mean to.
- The name in the audit trail is whatever someone typed in Settings.
- The rate limits are approximate. They stop casual overuse, not a determined attacker. To
  close the site later, use Netlify's password protection (check which plan has it) or add a
  check in netlify/functions/_lib.mjs.
- Watch Netlify's Usage page. Free plans cap builds, function calls and bandwidth each month.
- If the key leaks, make a new one in AI Studio, delete the old one, update AI_API_KEY and
  redeploy.
- The P&IDs, OPLs, datasheets, interlocks and maintenance history are part of the page. The
  shared database only holds what people add on top.


UPDATING
-----------------------------------------------------------------------------------------
Every push to the deployed branch rebuilds and publishes the site. To rebuild the page on
your own computer:  python3 build.py  (writes knowledge-hub-integrated_BAP5.html and
dist/index.html).


TRYING IT LOCALLY FIRST (optional)
-----------------------------------------------------------------------------------------
Needs Node.js 18 or newer and Python 3.
      npm install
      npm run build
      LOCAL_STORE_DIR=/tmp/akp AI_PROVIDER=mock node tools/devserver.mjs 8888
Open http://localhost:8888. The mock provider gives canned answers, so no key is needed. To
try Gemini locally, use  AI_PROVIDER=gemini AI_API_KEY=your_key  instead of AI_PROVIDER=mock.
Tests:  npm test
